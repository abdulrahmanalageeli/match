# Public profile edits and discovery pause

Migration: `20261107103336_member_profile_lifecycle.sql`. This change is local and has not been deployed.

- An approved member can submit a changed public profile once per rolling 30 days. PostgreSQL locks the member row and enforces the interval; a rejected update rolls back all profile/consent changes. `user.nextPublicProfileEditAt` gives the next eligible instant, or `null` when available.
- Initial applications and corrections while a submitted edit is pending remain usable. Private assessment/preference updates do not consume the public-edit allowance. New public Beena stories, profile-portrait replacements, and public gallery additions participate in review and the same allowance. The gallery has no reorder operation.
- Privacy reductions remain immediate: removing a portrait/gallery image, restricting portrait disclosure, withdrawing sensitive publication/assessment consent, or unsharing a Beena story is not held for the monthly date. An unrelated public edit cannot be bundled with a consent withdrawal to bypass the limit.
- `user.profileReviewPending` identifies a member-requested edit of a previously approved profile. Accepted direct and family conversations remain available while membership is valid. Discovery and new requests remain unavailable until approval. Peers see the previous approved public text; profile/gallery photos are hidden until review finishes. Consent withdrawal also removes corresponding content from the retained snapshot immediately.
- Discovery pause closes pending requests/unaccepted nominations, hides the member from discovery, and stops new requests. It preserves accepted requests and mutually accepted curated introductions. Conversation history, replies, read receipts, private photo grants, voice, relationship steps, and consented family rooms use accepted-relationship eligibility rather than directory compatibility.
- Blocks, ended relationships, suspension, unpaid membership, invalid sessions and withdrawn family consent continue to deny the corresponding access. Administrative suspension clears the pending-edit exception; approval clears the old snapshot but does not reset the 30-day date.
- The two named fields are optional in the phone-side type for older/demo responses. Settings and gallery mutation callbacks refresh account state. The local UI cannot enforce a remote database that has not received this migration.
- The older SQLite service is an explicit development-only option (`DEV` plus `VITE_MARRIAGE_BACKEND=local` without an environment mode). It is not used by the supported production/native Supabase build and has not been changed by this migration.
- Completing onboarding later stores answers only. New photo selection, removal and reveal/blur changes are not persisted; a warning requires acknowledgement before leaving with unsaved photo changes. No clear photo is added to local draft storage.

Validation uses the disposable PGlite PostgreSQL harness with synthetic users and receipts. This is not hosted Supabase, live email, StoreKit, or native iPhone verification. The CLI local advisor command cannot run without the local Supabase PostgreSQL service; role grants and fixed search paths are separately exercised by the lifecycle tests.
